RESEARCH PAPER INFO PACK
Project: Comparative Analysis of Prompt Engineering vs. Context Engineering Techniques
for Hindi/Hinglish Student Question Answering in Resource-Constrained Environments

PROJECT GOAL
- Identify which prompting or lightweight context strategies produce the best
  quality-cost tradeoff for Hinglish student QA when resources are limited.

PROBLEM STATEMENT
- LLMs vary widely by prompt design. In constrained settings, we must balance
  quality with latency and token usage. The study compares multiple techniques
  on a Hinglish QA dataset to determine the best tradeoffs.

KEY DEFINITIONS
- Prompt Engineering: instructions/examples/formatting to steer the model.
- Context Engineering (lightweight): reasoning structure or pseudo-context
  added inside prompts without external retrieval.
- Resource-Constrained: small/fast models, strict token budgets, low latency.

KEY FINDINGS (200-SAMPLE COMPARISON: 8B vs 70B)
- 70B Model Latency: Significantly faster (0.2-0.8s vs 2.1-4.3s for 8B)
- 70B Model Token Usage: Lower token counts across all techniques (37-84 vs 140-268)
- 8B Model Quality: Higher LLM-as-judge scores (7.15-7.46 vs 6.22-6.57)
- Trade-off observation: Larger model is faster but potentially lower quality per LLM-judge
- Cost-efficiency winner (quality/latency): 8B model for this QA task
- Latency winner: 70B model (practical constraint advantage)
